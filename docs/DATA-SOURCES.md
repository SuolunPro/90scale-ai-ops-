# 数据采集链路与备用渠道研究

记录当前链路、实测状态、可替换方案（含合规与成本）。实测时间：2026-11-18（北京时间）。

## 一、现有链路

| 渠道 | 用途 | 端点 | 实测 |
| --- | --- | --- | --- |
| 体彩官方 | 全池赛程/赔率（权威源） | `webapi.sporttery.cn/gateway/jc/football/getMatchCalculatorV1.qry` | HTTP 200，约 92 KB，330 ms |
| 球来了 | 第三方竞彩镜像（赔率、场次补充） | `qiulaile.vip/api/matches?matchType=0&mode=full` | HTTP 200，约 47 KB，254 ms |
| FotMob | xG、球队状态、赛果 | `www.fotmob.com/api/data/…` | HTTP 200，约 32 KB，140 ms |
| 澳客 | 竞彩页面、比分参考 | `www.okooo.com/jingcai/<日期>/` | HTTP **405**（反爬拦截） |
| LOTA | 私人引擎内的数据源 | 不在公开仓库 | 未验证 |

结论：主链路（官方 + 球来了 + FotMob）健康；澳客在服务器出口 IP 被反爬拦截，属已知 WARN，
不影响主流程，但不能把它当唯一来源。

## 二、澳客 405 的处理顺序

1. 带完整浏览器头（UA + Accept-Language + Referer），必要时带 Cookie —— 已部分生效，仍 405。
2. 降低频率、加随机延迟，避免被判定为爬虫。
3. 改用移动端/子域接口（`m.okooo.com`），字段更少但更容易通过。
4. 放弃抓取页面，改用其公开数据接口（若有）。
5. 用备用渠道替代（见下）。

注意：抓取第三方站点需遵守其 robots 与服务条款；不要高频、不要绕过登录/付费墙。

## 三、备用渠道候选

| 渠道 | 能力 | 成本 | 合规/风险 | 建议 |
| --- | --- | --- | --- | --- |
| football-data.org | 欧洲主流联赛赛程/赛果 | 免费层（10 次/分钟） | 需注册 key，条款清晰 | **推荐**：作为赛果交叉核验 |
| TheSportsDB | 赛程、比分、球队 | 免费层（测试 key） | 免费层限流，字段一般 | 可作降级源 |
| OpenLigaDB | 德甲等 | 免费、无需 key | 覆盖联赛少 | 兜底 |
| API-Football (RapidAPI) | 覆盖广、含赔率 | 付费（免费层 100 次/天） | 需 key，条款清晰 | 预算允许时上 |
| Sofascore / Flashscore 非官方接口 | 覆盖最广 | 免费 | 违反 ToS，易被封 | **不推荐**用于生产 |
| 500.com / 网易彩票页面 | 中文竞彩 | 免费 | 反爬强，ToS 风险 | 仅人工核对 |
| 官方体彩（已用） | 权威 | 免费 | 无风险 | 保持为主源 |

## 四、建议的采集分层

1. **权威层**：体彩官方接口 —— 决定“卖什么、赔率多少”，任何冲突以它为准。
2. **镜像层**：球来了 —— 官方不可用时的临时替代，必须标记 `source=mirror`。
3. **核验层**：football-data.org（免费 key）+ FotMob —— 只用于赛果与 xG 交叉核验，不参与售卖。
4. **禁止层**：需要绕反爬、违反 ToS 的源，不接入自动化。
